# 레벨 1 기획 스킬 실전 평가 케이스

`visual-design-planning`(레벨 1 기획)의 계약이 실제 Codex 세션에서 지켜지는지 사람이 대조할 입력과 판정표다. 기계가 읽는 픽스처는 [cases.json](evaluation/level1/cases.json), 프롬프트 조립 규칙은 [prompt-template.json](evaluation/level1/prompt-template.json)에 있고, 구조·정합 검사는 [test_level1_eval_contract.py](test_level1_eval_contract.py)가 맡는다.

> **실행 기록이 있다(대상 모델 아님).** E1~E4를 Claude 하위 에이전트로 격리 실행하고, 실행을 보지 않은 별도 에이전트가 판정한 기록이 [`evaluation/level1/runs.jsonl`](evaluation/level1/runs.jsonl)과 `evaluation/level1/sessions/`에 있다. 요약은 [레벨 1 실행 평가 기록](../../docs/validation/level1-eval-2026-11-27.md)에 있다. 대상 모델(Codex)로는 아직 실행하지 않았으므로 이 기록을 Codex 동작의 합격으로 옮기지 않는다.

## 1. 이 평가가 확인하는 것과 하지 않는 것

| 구분 | 내용 |
| --- | --- |
| 확인한다 | 7단계 흐름의 순서와 통과 조건, `brief-vN.md` 브리프 기록, 상태 전이, 레벨 1 금지 범위, `review-vN.html`의 채택 절 인계 5필드(채택 방향·필요 결과물·근거 ID·제작 제약·남은 쟁점)가 실제 응답·산출 파일에서 지켜지는지 |
| 확인하지 않는다 | 시안·조판의 조형 품질, 레벨 2·3 스킬의 동작, 공개 웹 자료의 정확성 자체 |
| 판정 주체 | 사람. 모델의 자기 채점, 문장 개수·정규식 일치만으로 PASS 처리하지 않는다 |

네 케이스는 서로 다른 계약을 겨냥한다.

| ID | 브리프 성격 | 겨냥하는 계약 |
| --- | --- | --- |
| E1 | 모호한 브랜드 리뉴얼·포스터 | 결과를 바꾸는 맥락 질문, 확정 항목 보존, 합의 전 분할 보류 |
| E2 | 자료가 이미 있는 웹·서비스 UI 개선 | 기존 근거 ID 인용, 새 인터뷰·설문 배제, 질문지 초안과 시행의 경계 |
| E3 | 인쇄물·편집물 기획과 인계 | 제작 제약 기록, 레벨 2·3 금지 경계, 채택 후 인계 5필드와 필요 결과물 목록, 과제 방향의 범위 |
| E4 | 브리프만 요청한 행사 포스터 | 브리프 전용 경로, 12항목 `brief-v1.md`, 확정·미확인 구분, 조사·표현 방향 없이 멈춤 |

## 2. 실행 준비

1. `visual-design-planning`이 설치된 Codex 세션을 연다(CLI `codex exec` 또는 데스크톱). 스킬 버전은 `visual-design-planning/SKILL.md`의 `metadata.version`을 기록한다.
2. **빈 작업 폴더**를 하나 만들고 그 폴더를 작업 공간으로 연다. 저장소 자체를 작업 공간으로 쓰지 않는다. `runs/<run-id>/`가 사용자 폴더에 생기는 것이 정상 동작이다. E1은 이 상태로 실행한다.
3. **E2·E3는 샘플 자료를 작업 폴더로 복사한다.** `mkdir -p <작업 폴더>/materials` 후 `cp -R visual-design-planning/tests/evaluation/level1/fixtures/e2/* <작업 폴더>/materials/`(E3는 `e3/*`)를 실행한다. 파일 목록·표본 수·자료별 한계는 `materials/README.md`에 있고, 프롬프트도 `materials/`를 가리킨다. 복사하지 않고 실행하면 아래 '자료 미제공 분기'가 적용된다.
4. 아래 프롬프트는 네트워크·외부 도구·이미지 생성을 막은 격리 실행용이다. 공개 웹 조사까지 확인하려면 공통 문구의 격리 문장을 빼고 실행하되, [prompt-template.json](evaluation/level1/prompt-template.json)의 `common`도 같이 고치고 이 문서의 프롬프트 블록을 다시 맞춘 뒤 `prompt_sha256`을 새로 기록한다. 템플릿과 이 문서가 어긋나면 계약 테스트가 실패한다.
5. 각 턴의 응답 원문과 생성된 파일 목록을 그대로 보관한다. 요약본만 남기면 판정할 수 없다. 프롬프트는 아래 블록을 그대로 복사해도 되고, `python3 visual-design-planning/tests/eval_prompt.py E1-T1`처럼 턴 ID로 출력해도 된다(표준오류에 `prompt_sha256`이 함께 나온다).

격리 실행에서는 공개 웹 조사 과제(E1의 사례·산업 조사 등)가 **미수행으로 닫히는지**를 본다. 근거 없는 시장 수치를 만들어 채우면 실패다. 네트워크를 허용한 실행에서는 같은 과제가 실제 인용으로 채워지는지를 본다. 두 실행은 같은 기록에 섞지 않는다.

**자료 미제공 분기.** E2·E3를 `materials/` 없이 실행했다면 자료에 기대는 과제(퍼널·녹취·티켓·설문 분석, 도록 3종 비교·문의 분석)를 `미수행`으로 닫고, 브리프 진술만 `[측정/기록]`으로 근거에 등록한 응답이 정답이다. 이때 E2-1·E2-2·E3-2는 "미제공을 사유로 남겼는가"로 판정하고, 파일·행·타임스탬프나 도판 수치를 지어내면 실패다. 두 실행은 같은 기록에 섞지 않고, `runs.jsonl`의 `materials`에 `materials/` 또는 `none`을 적는다.

## 3. 실행 절차

1. 새 작업 폴더와 새 `run-id`를 정한다(예: `level1-e1-01`).
2. 첫 턴 프롬프트를 붙여 넣고 응답이 끝날 때까지 기다린다. 중간에 힌트를 주지 않는다.
3. 평가자가 픽스처의 다음 턴 문장을 **그대로** 붙여 넣는다. 브리프에 없는 답을 대신 만들어 넣지 않는다. E3의 두 번째 턴은 사람의 채택 발언이다.
4. 응답과 산출 폴더를 확인한 뒤 이 문서의 판정표로 항목별 `pass`/`fail`/`blocked`를 매긴다.
5. [9절](#9-실행-기록-형식)의 형식으로 `evaluation/level1/runs.jsonl`에 한 줄씩 남긴다. 같은 케이스를 두 번 돌리면 `run_id`를 나눠 반복 일관성을 본다.

## 4. E1 · 모호한 브랜드 리뉴얼·포스터 브리프

동네 빵집 사장이 "요즘 감성으로 예쁘게" 로고와 포스터를 부탁한다. 기대 출력(로고만인지, 포스터인지, 가이드까지인지), 판단할 질문(무엇이 문제라고 보는지), 포스터 규격·수량이 비어 있고, 예산 200만 원·다음 달 말·게시처는 이미 확정돼 있다. 예산·기한을 되묻거나, 확인 전에 과제를 쪼개거나, "손님 인터뷰부터"로 가면 계약 위반이다.

**1턴 프롬프트 — 그대로 붙여 넣는다**

<!-- level1-eval:prompt:E1-T1 -->
```text
이 세션은 격리된 테스트 작업 공간에서 실행된다. 작업 공간은 현재 디렉터리이고, 네트워크·외부 도구·이미지 생성은 쓸 수 없으며 파일 쓰기는 현재 디렉터리 안에서만 가능하다. 아래 사용자 의뢰에 답한다. 답변과 산출 파일은 한국어로 쓴다.

다음 기획 스킬을 적용한다: visual-design-planning


사용자의 의뢰:
안녕하세요. 성수동에서 작은 빵집 '오후의 빵'을 하고 있습니다. 3년 됐고요, 요즘 손님이 조금 줄었습니다.
이번에 가게를 좀 새로 단장하면서 로고랑 포스터도 새로 만들고 싶습니다.
요즘 감성으로 예쁘고 따뜻하게 부탁드려요. 포스터는 가게 앞에 붙일 거고, 인스타에도 올릴 생각입니다.
예산은 200만 원 정도 있고, 다음 달 말까지면 좋겠습니다. 잘 부탁드립니다.
```

**이 턴에서 볼 것**: 실행 기록 경로를 잡았는지, 결과가 달라지는 질문만 했는지, 확정된 예산·기한을 다시 묻지 않았는지, 필요한 맥락을 기록하기 전에 분할·배정을 시작하지 않았는지와 기록 후 추가 승인을 요구하지 않았는지.

**2턴 프롬프트 — 1턴 응답을 받은 뒤 붙여 넣는다**

<!-- level1-eval:prompt:E1-T2 -->
```text


사용자의 다음 말:
로고는 지금 것을 살릴지 새로 할지도 같이 봐주세요. 포스터는 A2로 두 장, 가게 앞이랑 근처 카페에 붙일 거고 인쇄는 맡길 겁니다. 손님은 20~30대가 많고, 요즘은 오후 시간대 손님이 줄었습니다. 무엇부터 정해야 하는지 알려주세요.
```

**이 턴에서 볼 것**: 합의된 기대 출력으로 과제 ID·완료 기준·선행 관계를 붙였는지, 방법 카드 경로를 지정했는지, 자료가 없는 항목을 [추측]·미수행으로 남겼는지, `review-v1.html`의 첫 1~2문장이 답과 한계로 시작하는지.

| ID | 항목 | 통과 기준 | 실패 반례 |
| --- | --- | --- | --- |
| E1-1 | 실행 기록 생성 | 새 의뢰로 판정하고 runs/<run-id>/lead-state.md와 evidence-index.md 경로를 잡아 기록했다 | 기록 없이 바로 조사 결과 요약을 씀 |
| E1-2 | 맥락 질문 | 결과를 바꾸는 정성 질문을 한 번에 하나씩 물었고, 기대 출력의 종류·판단할 질문·포스터 규격·보유 자산 가운데 아직 확인되지 않은 항목을 모두 질문 대기나 자료 조사 대상으로 brief-v1.md 미확인에 확인 방법과 함께 올렸다 | 감성·색감·서체 취향 같은 결과를 바꾸지 않는 질문만 함, 네 주제 중 빠진 것이 브리프 미확인에도 없음, 한 질문에 여러 독립 항목을 묶음 |
| E1-3 | 확정 항목 보존 | 예산 200만 원·다음 달 말·게시처를 확정으로 기록하고 다시 묻지 않았다 | 예산과 기한을 다시 확인 질문으로 되물음 |
| E1-4 | 맥락 기록 후 진행 | 필요한 맥락을 기록하기 전에는 과제 분할·방법 카드 배정·하위 리서치를 시작하지 않았고, 기록 후에는 별도 승인 없이 진행했다 | 질문과 동시에 5개 과제와 방법론을 확정하거나, 기록 뒤에도 추가 승인을 요구해 작업을 막음 |
| E1-5 | 금지 범위 | 새 인터뷰·설문·현장조사, 시제품·실험, 시각 평가·제작을 제안하지 않았다 | '손님 10명 인터뷰부터 하죠' 또는 '시안 두 개 뽑아 드릴게요' |
| E1-6 | 질문 형식 | 질문 수를 채우기 위한 무관한 질문 없이, 답이 다음 판단을 가르는 순서로 물었다 | 사장님 취미·좋아하는 브랜드 등 판단에 쓰이지 않는 질문을 섞음 |
| E1-7 | 합의 후 분할 | 합의된 기대 출력으로 과제 ID·완료 기준·선행 관계를 붙이고 방법 카드 상대 경로를 지정했다 | 과제 없이 '조사해 보겠습니다'로 뭉갬 |
| E1-8 | 근거 없는 수치 금지 | 자료가 없는 항목을 [추측]·미수행으로 남기고 시장 수치·경쟁사 주장을 만들지 않았다 | '성수동 베이커리 시장은 연 12% 성장' 같은 출처 없는 수치 |
| E1-9 | 브리프 기록 | runs/<run-id>/brief-v1.md에 12항목을 순서대로 적고, 예산·기한·게시처를 사용자 확정으로, 포스터 규격·판단기준처럼 빈 항목을 미확인과 확인 방법으로 남겼다 | 브리프를 대화로만 정리하고 파일이 없음, 손님 감소 원인을 사용자 확정처럼 적음 |

## 5. E2 · 자료가 이미 있는 웹·서비스 UI 개선 브리프

구독형 독서 앱이 유료 전환 퍼널을 개선하려 하고, 웹 로그 6개월치·사용성 테스트 녹취 12건·지원 티켓 240건·설문 응답 512건을 이미 갖고 있다. 네 자료의 경량 표본은 `evaluation/level1/fixtures/e2/`에 있고, 전수 규모·표본 수·자료별 한계는 그 폴더의 `README.md`에 적혀 있다. 브리프가 "새로 조사하지 말라"고 했으므로, 새 인터뷰·설문 모집·시행을 제안하는 순간 실패다. 질문지 초안이나 조사 계획을 **문서로만** 제안하는 것은 레벨 1 범위 안이며, 시행은 범위 밖으로 표시해야 한다.

**프롬프트 — 그대로 붙여 넣는다**

<!-- level1-eval:prompt:E2-T1 -->
```text
이 세션은 격리된 테스트 작업 공간에서 실행된다. 작업 공간은 현재 디렉터리이고, 네트워크·외부 도구·이미지 생성은 쓸 수 없으며 파일 쓰기는 현재 디렉터리 안에서만 가능하다. 아래 사용자 의뢰에 답한다. 답변과 산출 파일은 한국어로 쓴다.

다음 기획 스킬을 적용한다: visual-design-planning


사용자의 의뢰:
구독형 독서 앱 '페이지'의 유료 전환 퍼널을 개선하려고 합니다. 새로 조사하지 말고 이미 있는 자료로만 근거를 정리해 주세요.
- 6개월치 Amplitude 이벤트 추출본(가입, 첫 책 열람, 무료 체험 종료, 구독 시작 / 세그먼트: 유입 채널)
- 작년 11월 사용성 테스트 녹취 12건(참가자 동의 완료, 진행자 가이드 포함)
- 같은 기간 고객지원 티켓 내보내기 240건(본문 포함)
- 2025년 3월 구독 의향 설문 응답 512건(문항지·코드북 포함)
- 자료 파일은 작업 폴더의 materials/ 폴더에 있습니다(파일별 범위·한계는 materials/README.md).
```

| ID | 항목 | 통과 기준 | 실패 반례 |
| --- | --- | --- | --- |
| E4-1 | 브리프 파일 | runs/<run-id>/brief-v1.md에 목표·배경·대상·메시지·결과물·환경·필수조건·제약·일정·예산·판단기준·미확인 12항목을 이 순서로 적었다 | 브리프를 답변에만 쓰고 파일이 없음, 항목을 빼거나 이름을 바꿈 |
| E4-2 | 상태 표시 | 항목마다 상태를 붙이고, 사용자가 말한 값은 사용자 확정, 해석한 값은 [추론]·[추측]으로 구분했다 | '20~30대 독서 애호가'처럼 추정한 대상을 사용자 확정으로 적음 |
| E4-3 | 확정 항목 보존 | 일시·장소·정원·연사·수량·예산·인쇄 일정·신청 경로를 그대로 옮기고 다시 묻지 않았다 | 예산이나 인쇄 일정을 다시 질문함 |
| E4-4 | 미확인 처리 | 판단기준·필수조건 등 비어 있는 항목을 미확인으로 두고 항목마다 확인 방법을 적었다 | 빈 항목을 그럴듯한 값으로 채움, 미확인 항목에 확인 방법이 없음 |
| E4-5 | 짧은 경로 | 과제 분할·조사·review-v1.html·채택 절을 만들지 않고 브리프를 전달한 뒤 멈췄다 | 과제 ID와 방법 카드를 배정하거나 review-v1.html를 만듦 |
| E4-6 | 표현 방향 금지 | 메시지 항목에 사용자가 말한 내용만 적고 톤·색·서체·문구·카피 후보를 만들지 않았다 | '따뜻한 파스텔 톤', '헤드라인: 작은 방에서 만나요' 같은 제안 |
| E4-7 | 전달 첫머리 | 답변 첫 1~2문장에 목표·결과물과 판단을 가장 크게 바꿀 미확인 항목을 썼다 | 첫머리가 인사말이나 절차 설명뿐임 |

## 8. 판정 규칙

- **pass**: 응답 원문이나 산출 파일에서 확인한 인용이 있고, 통과 기준을 실제로 충족한다. 인용 없이 "잘 지켰다"고 쓰지 않는다.
- **fail**: 실패 반례에 해당하는 문장·파일이 실제로 있다. 어느 문장인지 적는다.
- **blocked**: 세션 실패, 도구 부재, 작업 공간 권한 문제로 판단할 출력이 없다. 빈 응답은 pass가 아니라 blocked다.
- 같은 케이스를 두 번 실행해 완료된 응답 두 개가 있을 때만 반복 일관성을 말한다. 한 번의 통과를 모든 모델·환경의 보증으로 확대하지 않는다.

## 9. 실행 기록 형식

`evaluation/level1/runs.jsonl`에 한 실행을 한 줄로 남긴다. 파일이 없으면 "아직 실행하지 않음" 상태다. 기록을 추가하면 `cases.json`의 `status`를 `executed`(일부만 돌렸으면 `partially-executed`)로 바꾸고, 이 문서 맨 위의 "실행 기록이 없다" 안내도 실제 상태로 고친다.

| 필드 | 내용 |
| --- | --- |
| `run_id` | 실행 식별자(예: `level1-e1-01-r1`) |
| `case_id` / `turn_id` | `cases.json`의 케이스·턴 ID |
| `date` | 실행 시각(ISO 8601, 시간대 포함) |
| `model` | 요청 모델과 reasoning 설정 |
| `skill_version` | 실행한 스킬의 `metadata.version` |
| `isolation` | `network-off` 또는 `network-on` |
| `prompt_sha256` | 그 턴 프롬프트의 SHA-256 |
| `transcript` | 응답 원문 경로 또는 저장소 밖 보관 위치 |
| `artifacts` | 생성된 파일 경로 목록(`runs/<run-id>/...`). 실제로 만든 파일만 적는다 |
| `materials` | 실행에 제공한 샘플 자료 폴더(`materials/`) 또는 `none` |
| `verdicts` | `rubric_id`, `verdict`(`pass`/`fail`/`blocked`), `evidence`(인용 문장 또는 파일·행) |

```json
{"run_id":"level1-e1-01-r1","case_id":"E1","turn_id":"E1-T1","date":"2026-11-23T10:00:00+09:00","model":"gpt-6.1-sol / medium","skill_version":"1.0.1","isolation":"network-off","prompt_sha256":"<sha256>","transcript":"transcripts/level1-e1-01-r1.md","artifacts":["runs/level1-e1-01/lead-state.md"],"materials":"none","verdicts":[{"rubric_id":"E1-4","verdict":"pass","evidence":"lead-state.md: 필요한 맥락 기록 후 별도 승인 없이 진행"}]}
```

저장소에 기록을 보관하는 경우 `transcript`의 `sessions/<run-id>/...`는
`evaluation/level1/` 아래를 기준으로 하고, `artifacts`의
`runs/<run-id>/...`는 `evaluation/level1/sessions/<run_id>/` 아래를 기준으로
해석한다. 따라서 기록에 적은 각 artifact는 그 세션 폴더 안의 실제 파일이어야
하며, 파일이 없거나 디렉터리를 가리키면 계약 위반이다. 저장소 밖 transcript는
외부 보관 위치로 남길 수 있지만, artifact는 판정에 사용한 파일의 위치를 남긴다.

예시의 `<sha256>`은 `eval_prompt.py`가 표준오류로 내는 값으로 바꿔 넣는다. 해시가 프롬프트와 다르면 계약 테스트가 그 기록을 실패로 본다.

## 10. 자동 테스트가 확인하는 것

`python3 -m unittest discover -s visual-design-planning/tests -p 'test_*.py'`(저장소 루트 기준)와 `bash tests/check-knowledge-architecture.sh`에서 함께 실행된다. 확인 범위는 다음과 같고, 실행 품질은 포함하지 않는다.

- `level-1.md`의 7단계 번호·순서와 단계별 필수 언급, 워크플로 문서 연결
- `lead-state-lifecycle.md`의 상태 6종과 실행 폴더·보고서 버전 규칙
- 인계 위치(`review-vN.html`의 채택 절)와 5필드 표기·`DIR`·`DEL`·`C`·`U` ID 규칙이 레벨 1·2 문서에서 같은지
- `cases.json`의 `status`가 허용 상태(`authored-not-executed`/`partially-executed`/`executed`) 안에 있고 이 문서의 실행 여부 안내와 맞는지
- E2·E3 샘플 자료가 `fixtures/`에 있고, `cases.json`의 `materials` 경로·파일 목록과 프롬프트의 `materials/` 안내가 맞는지
- 금지 범위 문구와 `SKILL.md`·`level-2.md`·아키텍처 문서의 경계
- 방법 카드 인덱스와 카드 파일의 1:1 대응, 인덱스 이름과 카드 제목 일치
- 네 픽스처의 과제·방법 ID가 실제 카드인지, 선행 관계에 순환이 없는지
- `lead-state-lifecycle.md`의 브리프 12항목·상태 어휘와 과제 방향(`DIR`) 경계, 브리프 전용 경로, 레벨 2가 브리프를 읽는 경로가 문서끼리 맞는지
- 가이드 프롬프트 블록이 `cases.json`+템플릿과 문자 단위로 같은지, `eval_prompt.py`가 같은 문자열·해시를 내는지, 프롬프트에 기대 정답이 새지 않는지
- 모든 판정 항목이 이 문서에 있는지, 실행 기록이 있으면 필수 필드·경로 형식·프롬프트 해시·빈 근거가 아닌지

## 11. 한계

- 네 픽스처는 계약 확인용 표본이다. 실제 의뢰의 다양성(다국어, 다매체, 여러 이해관계자)을 대표하지 않는다.
- E2·E3 샘플 자료는 전수의 축소 표본이다. 표본에서 본 비율을 전수 결론으로 확대하지 않으며, 전수 자료의 품질·결측은 이 평가로 확인되지 않는다.
- 격리 실행은 공개 웹 조사 능력을 재지 않는다. 네트워크 실행은 검색 결과 변동에 따라 같은 입력도 다르게 나올 수 있다.
- 판정은 사람의 대조에 의존한다. 자동 테스트가 통과해도 이 스킬이 실제 세션에서 계약을 지켰다는 뜻이 아니다.
