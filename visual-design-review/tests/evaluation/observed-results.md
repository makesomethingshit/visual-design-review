# 관측 판정 — 의미와 형식을 분리

평가자는 메인 에이전트이며 원문과 사례를 직접 대조했다. 이는 사람 사용자 평가나
통계적 유효성 검증이 아니다. 독립 읽기 전용 에이전트의 보조 검토는 별도로 보고한다.

판정 축:
- **D 결정**: 예상한 실제 결함을 탐지하고 근거 없는 결함을 만들지 않았는가.
- **E 근거 완전성**: 위치/자료·영향·의도/반대 해석·조치·검증 조건이 있는가.
- **O 범위**: 직접 관찰과 설명, 판독 불가/미검증을 구별했는가.
- **P 표현**: 중복·가독성. 아홉 제목 유무는 합격 요건이 아니다.
`불완전`은 전체 응답이 잘못됐다는 뜻이 아니라 해당 필수 내용이 빠졌다는 뜻이다.

## 첫 실행, 같은 입력의 baseline/skill 대조
각 원문은 runs.jsonl의 `behavior-<ID>-<arm>-1` 레코드 response다.

| 사례 | baseline 관측 | skill 관측 | 비교 결론 |
| --- | --- | --- | --- |
| A | 의도된 난독성을 결함으로 만들지 않고 실제 관찰 유보 | 같은 핵심 결정, conditional Strength·회귀 확인 포함 | 결정상 우열 근거 없음. 사용자 설명의 기능 효과를 가설로 명시 |
| B | 대상 아래 위치·정렬 처방을 먼저 제시, 공통 캡션 가능성도 언급 | 대상 확인을 먼저 요구하고 Minor/Probable로 조건화. 큰 영향은 미확인 | 둘 다 Major 없음. skill의 잠정 Minor도 영향 확인 전이라 보수성 한계 기록 |
| C | 서로 다른 근거를 같은 기호로 표시하는 것을 결함이라 단정하나 진위는 유보 | 핵심 목표를 가정하고 주변 설명/범례 미확인인데 Major/Probable 부여 | 둘 다 영향 단정 위험. skill은 D 실패(과잉 심각도). 전체 설명 통합은 허용했고 E는 충실 |
| D | 시각 품질 유보, 자료 부족을 작품 결함으로 만들지 않음 | 같은 결정, 단색을 보편 합격선으로 강요하지 않음 | 결정상 우열 근거 없음 |
| E | 입력 요청. 이후 '화면/사용 흐름'으로 약간 UI 범위 이동 | 입력 요청, 관찰/장단점 유보 | 둘 다 결함 발명 없음; skill이 요청 영역을 더 좁게 유지 |
| F | 틀린 날짜 탐지·수정. 승인 브리프와 일치 확인을 명시적 후속 검증으로는 안 씀 | Defect/Critical/Confirmed, 제공 문안의 필수 목표 실패 근거와 수정 후 대조/독해 검증 | D 둘 다 탐지. E는 skill이 더 명시적이나 단일 사례의 개선을 일반화하지 않음 |
| G | PPI 미달 탐지, RGB 충족, 실물 미검증 분리 | 같은 결정. Major/Confirmed, 예외 승인 또는 교체 후 preflight 검증 | D 둘 다 탐지. Critical을 무조건 강요하지 않음 |
| H | 실제 이미지는 없음을 밝히고 일부 페이지/캡션/원본 속성 범위 구분 | 보고 기반임을 밝히고 같은 구분. 판독 불가를 작품 결함으로 만들지 않음 | 둘 다 O 충족; 실제 다페이지 관찰 시험은 아님 |
| I | 진동/크롭을 오류로 만들지 않고 비교·검증 방향 | 조건부 해석, 정확한 색 수치/원본 내용 날조 없음 | 둘 다 D/O 충족, 미감 처방 강요 없음 |
| J | 실제 패널 관찰. B 정렬 기준·D 색 비중을 더 선명히 해야 한다는 처방은 목적 대비 근거 약함. 검증 조건이 일부 부족 | 자리표시자/가상 데이터 구별. B/C에 조건부 설명하면서 Minor/Confirmed·Probable이 혼재. 유지 설명의 회귀 검증 일부 누락 | 둘 다 관찰된 요소는 대체로 부합하나 E/심각도 완전 통과 아님. 선택 실험을 필수 수정처럼 읽지 않게 보정 필요 |

합계 점수·승률을 만들지 않는다. 사례 가중치와 정답 severity가 사전 확정되지 않았고,
표본도 작다. 공통적으로 날짜/규격의 실제 실패를 탐지했고 이미지 없는 시각 날조는
관측되지 않았다. 그러나 C의 과잉 Major와 J의 근거/검증 누락 때문에 '전부 통과'가 아니다.

## 보정과 회귀
C의 결과를 근거로 최종 rubric은 핵심 목표 가정/주변 설명에 의존하는 영향의
심각도를 확인 전 확정하지 않도록 일반 문턱을 보강했다. 영향 자체가 미확인인
경우 Minor로 자동 낮추지도 않는다. 색/이미지 부재와 와이어프레임 처리도
프로토콜에 명시했다. 이 최종 보강은 구조 검사만 완료했고 모델 재실행은 한도로
막혔다. 기존 원문은 시험 당시 snapshot에만 귀속한다.

A~E의 기존 핵심 무회귀 조건(설명 기반 한정, 의도된 규칙 위반 자동 결함 금지,
자료 부족 결함 금지, 이미지 없으면 입력 요청)은 첫 실행에서 유지됐다. 다만
C의 severity를 포함한 엄격한 최종 합격은 보류다.

## 반복과 라우팅
두 번째 실행은 baseline A만 완료했다. 두 A 응답 모두 의도된 난독성을 자동
결함으로 만들지 않았다. 다른 사례나 skill arm의 반복 안정성은 검증하지 못했다.
31개 차단 레코드는 usage-limit 오류이며 품질 실패/통과로 세지 않는다.

R1 명시, R2/R3 암시, R4 CSS, R5 UI 접근성, R6 일반 코드 리뷰는 두 번씩 시도했으나
모두 실행 전 한도 차단이었다. 별도 [초기 probe](routing-probe.json)는 암시 요청에서 스킬 선택을
선언했으나 읽기가 차단됐다고 모델이 보고했다. 실제 파일 읽기 이벤트가 없어
정책 차단의 원인도 독립적으로 확인하지 못했다. 선언을 활성화 성공으로 세지 않는다. 네이티브
긍정/음성 라우팅은 미검증이다.
