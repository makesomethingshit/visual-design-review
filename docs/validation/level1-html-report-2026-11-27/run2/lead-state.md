## 맥락 확인과 중간 조건 합의
- 질문: (Q) 60대 이상 처음 쓰는 손님이 점심 줄 앞 키오스크에서 주문을 포기하는 이유를 공개 근거로 볼 때 "글씨가 작아서"로 정의하는 것이 맞는가, 아니면 어떻게 다시 정의해야 하며, 시안에서 쓸 원칙·과제 방향은 무엇인가.
- 출력: 템플릿 기반 HTML 검토 보고서(문제 재정의, 원칙, DIR 후보), 대상 독자 디자이너·본부.
- 범위: 공개 연구·조사·지침·법령. 국내 우선, 해외는 보조. 신규 설문·인터뷰·현장조사·시안 없음.
- 자료: 자사 화면·이용 기록 없음(사용자 확정).
- 판정할 수 없는 범위: 자사 화면의 실제 막힘 위치, 분식 메뉴 구조의 영향, 자사 매장 법령 적용, 개선 효과.
- 질문 이력: 사용자가 "추가 질문은 보고서를 본 뒤에 받겠다"고 밝혀, 결과를 바꾸는 정성 질문(목표의 뜻)은 보고서 끝에 한 개만 둔다. 중간 조건 합의는 승인 절차로 쓰지 않음.
