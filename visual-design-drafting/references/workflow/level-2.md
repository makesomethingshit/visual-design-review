# 레벨 2 실행 흐름

레벨 2는 레벨 1이 확정한 판단을 조형으로 옮기고, 같은 조건에서 비교할 수 있는 시안을 만든 뒤, 사람이 고른 하나를 제작 가능한 스펙으로 닫는다. 아래 네 단계는 한 번 통과하는 고정 순서가 아니라 결정이 바뀌면 이전 단계로 돌아가는 흐름이다. 단계마다 실행 폴더에 파일 하나가 남고, 다음 단계는 그 파일을 읽어 시작한다.

레벨 2가 대신하지 않는 일: 레벨 1의 자료 조사·방법 카드·근거 작성, 레벨 3의 비평·심각도 판정·출력 프리플라이트. 근거 없는 값·팔레트·비율을 채우지 않고, 사람의 채택을 대신 결정하지 않는다.

## 0. 실행 폴더와 산출물

레벨 1 실행 폴더(`runs/<run-id>/`)가 있으면 그 아래 `drafts/`에 레벨 2 기록을 둔다. 레벨 1 없이 직접 브리프로 들어왔으면 새 `runs/<run-id>/drafts/`를 만들되 `lead-state.md`·`evidence-index.md`는 만들지 않는다(둘은 레벨 1 산출물이다). 실행 폴더의 절대 경로를 `10-intake.md` 첫 줄에 적는다.

| 단계 | 파일 | 남기는 내용 |
| --- | --- | --- |
| 1 | `drafts/10-intake.md` | 레벨 1 인계에서 읽은 채택 방향·필요 결과물·근거 ID·제약·미결, 필요 결과물의 시안 트랙 매핑, 결손 처리, 인계 판정 |
| 2 | `drafts/20-translation.md` | 조형 변수별 값·단위·식, 근거 ID 또는 가정·미결 상태 |
| 3 | `drafts/30-evidence-map.md`, `drafts/draft-a/`·`draft-b/`(필요 시 `draft-c/`) | 시안 산출물과 근거 추적 표 |
| 4 | `drafts/40-selection.md`, `drafts/handoff-v1.md`, `drafts/final/` | 선택·수정 기록, 확정 시안 사본, 제작 스펙 |

시안 폴더마다 진입 파일 하나와 기록을 둔다: 실제 렌더되는 진입 파일(`index.html`, `artboard.svg` 등), 확인용 캡처(`preview.png`), 그 시안의 기록(`draft.md`). 어느 파일이 진입점인지 `drafts/INDEX.md`에 한 줄씩 적는다.

## 1. 인계 자산 로드 · 정합 확인

### 1.1 읽을 파일 정하기

1. 사람이 파일을 지목했으면 그것을 연다.
2. 지목이 없으면 실행 폴더의 `review-v1.html`부터 번호가 매겨진 검토 보고서 중 번호가 가장 높은 파일을 열되, `lead-state.md`의 사람 판정·시점과 맞는지 확인한다.
3. 채택 기록이 없거나 반려로 끝났으면 채택 여부를 사람에게 묻는다. 리뷰 문장에서 "가장 나은 방향"을 추정해 채택으로 대신하지 않는다.
4. 채택 절 첫 줄이 가리키는 `brief-vN.md`를 연다. 가리키는 줄이 없으면 실행 폴더에서 번호가 가장 높은 브리프를 열고 그 사실을 `gaps`에 적는다.
5. 리뷰가 없고 레벨 1이 브리프만 남겼으면(브리프 전용 경로) `brief-vN.md`를 직접 브리프로 읽고 §1.7로 간다. 인계 파일이 아예 없어도 §1.7로 간다.

네 파일에서 가져오는 것이 다르다.

| 파일 | 가져오는 것 |
| --- | --- |
| `review-vN.html`(예: `review-v1.html`) | 시안이 답해야 할 질문과 범위, 채택 절(`<section id="adoption">`)의 채택 방향·필요 결과물·근거 ID·제작 제약·남은 쟁점, 주장별 근거 위치, 완료 기준과 남은 한계 |
| `brief-vN.md` | 목표·대상·메시지·환경·필수조건·판단기준과 항목별 상태, 미확인 항목 |
| `evidence-index.md` | 근거 ID, 원문 위치, 대상·조건, 발췌, 한계·반례 |
| `lead-state.md` | 사람의 판정과 시점, 확정된 제약, 남은 쟁점의 결정 주체, 보고서 버전 |

### 1.2 `review-vN.html`에서 읽는 순서

레벨 1의 검토 보고서는 HTML이다([보고서 형식](../../../visual-design-planning/references/workflow/report-format.md)). 표지 요약(`.summary`)의 첫 1~2문장에 합의한 질문에 대한 답과 판단을 바꿀 한계가, 채택 절(`<section id="adoption">`)에 다섯 필드(채택 방향, 필요 결과물, 근거 ID, 제작 제약, 남은 쟁점)가 필드 이름 `<h3>`과 표로 있다. 채택 방향에 딸린 디자인 원칙(동작·배치 규칙)은 채택 절의 제작 제약 `C-xx`로 넘어온다. 인계는 별도 `handoff.md`가 아니라 보고서 안의 채택 절이다. 그 순서대로 읽는다.

| 문서 위치 | 읽는 것 | `10-intake.md`로 옮기는 필드 |
| --- | --- | --- |
| 표지 요약 첫 1~2문장 | 합의한 질문에 대한 답, 판단을 바꿀 한계 | `question`, `scope_limit` |
| 채택 절 | 채택 방향, 필요 결과물, 근거 ID, 제작 제약, 남은 쟁점 | `adopted`, `deliverables`, `constraints`, `unresolved` |
| 주장별 근거 | 주장 → 근거 ID → 원문 위치, 근거 수준, 예외 | `evidence` |
| 완료 기준·한계 | 충족·미충족 항목, 자료의 공백 | `gaps` |
| `lead-state.md`의 사람 판정 | 채택 시점, 반려된 안과 사유, 결정 주체 | `decision` |

채택 절이 없는 리뷰는 아직 인계서가 아니다. 방향을 사람이 골랐는지 한 번 묻고, 고르지 않았으면 `PARTIAL`로 두고 후보 방향을 시안 차이 축으로 옮길 수 있는지 사람과 확인한다. 레벨 1이 채택 절 대신 별도 `handoff.md`를 남겼다면 그것을 인계서로 승격하지 않고, 채택 절로 옮겨 적을 수 있는지 사람에게 확인한다.

### 1.3 근거 ID 처리

- `evidence-index.md`의 ID를 표기 그대로 쓴다. 번호를 다시 매기거나 이름을 바꾸지 않는다.
- 채택 절의 인계 ID도 마찬가지다. `DIR-xx`(방향)·`DEL-xx`(필요 결과물)·`C-xx`(제약)·`U-xx`(쟁점)를 표기 그대로 `10-intake.md`로 옮기고, 레벨 1 문서에 없는 ID를 새로 만들지 않는다.
- `DEL` 목록은 품목 단위 인계다. 레벨 1이 정한 우선순위를 다시 매기지 않고, 각 항목이 어느 시안 트랙(`draft-a/`·`draft-b/`·필요 시 `draft-c/`)에서 다루어지는지 `draft_track`에 적는다. 인계에 없는 품목을 시안에 새로 만들지 않고, 필요하다고 보면 사람에게 `DEL` 추가를 요청한다.
- 레벨 1이 채택 절에 ID를 붙이지 않았으면(이전 버전 리뷰 등) `10-intake.md`에서 읽은 순서대로 부여하고 `id_origin: LEVEL2_NORMALIZED`로 부여 주체를 적는다. 원칙은 [레벨 1 인계 기록](../../../visual-design-planning/references/workflow/lead-state-lifecycle.md)의 '인계 기록' 절에 있다.
- 리뷰가 ID 없이 주장만 적었으면 `evidence-index.md`에서 같은 원문을 찾아 ID를 연결한다. 끝내 없으면 `NO-EVIDENCE`로 표시하고, 그 주장에 기대는 시안 값은 `NEW`(가정·후보)로 둔다.
- 문서에 없는 ID나 원문 위치를 만들지 않는다. 인용 별칭이 필요하면 `ALIAS-01`처럼 별도 접두어를 쓰고 원문 위치를 함께 적는다. 별칭은 근거 ID로 승격되지 않는다.

### 1.4 필요 결과물 → 시안 트랙 매핑

인계받은 `필요 결과물`을 시안 트랙에 매핑한다. 어떤 시안이 어느 품목·매체를 다루는지 정하지 않으면, 인계받은 목록과 실제로 만든 시안이 어긋난 채로 남는다.

| `DEL` ID | 품목·매체 | 우선순위 | 다루는 시안 트랙 | 비고 |
| --- | --- | --- | --- | --- |
| DEL-01 | A2 포스터 · 오프셋 인쇄 | 1 | draft-a, draft-b | 두 시안이 같은 판형·원고로 비교 |
| DEL-02 | 인스타 4:5 이미지 | 2 | draft-a, draft-b | 시안 1개당 1장, 포스터의 축소 규격 |

- 모든 `DEL` 항목은 하나 이상의 시안 트랙에 매핑되거나, 시안에서 빼는 이유를 적는다. 매핑되지 않은 항목을 조용히 빠뜨리지 않는다.
- 한 시안 트랙이 여러 `DEL`을 다루면 그 트랙의 `draft.md`에 어느 `DEL`을 다루는지 적는다. 트랙이 다른 품목을 섞어 하나의 시안처럼 보이게 하지 않는다.
- 우선순위는 시안 제작·검토 순서의 기준으로 쓰고, 레벨 2가 임의로 바꾸지 않는다. 먼저 만들 `DEL`이 비교 시안의 공통 조건을 정한다.
- 품목이 여러 개면 품목별로 비교 시안을 만들지, 한 시안이 여러 품목을 함께 다를지를 사람과 확인한다. 확인 전에는 판형이 같은 품목부터 한 트랙에 묶고 그 사실을 적는다.

### 1.5 정합 확인 항목

| 확인 항목 | 확인 방법 | 어긋날 때 |
| --- | --- | --- |
| 판형·매체·마감 | 채택 절과 `lead-state.md`의 제약 대조 | 사람에게 확인. 시안 구조가 달라지므로 §2 전에 멈춘다 |
| 필요 결과물(`DEL`) 목록 | 채택 절의 항목별 품목·매체·목적·우선순위·연결 근거 ID 확인 | 빠진 항목·모순된 매체는 사람에게 확인. 시안 구조가 달라지므로 §2 전에 멈춘다 |
| `DEL` → 시안 트랙 매핑 | §1.4 표와 인계받은 목록 대조 | 매핑되지 않은 항목은 이유를 적고 사람에게 확인 |
| 실제 원고 | 원문 텍스트·파일 확보 여부 | 예시 원고로 시험하고 `EXAMPLE-COPY`로 표시. 줄바꿈·수용량은 UNVERIFIED |
| 자산(이미지·로고·서체) | 파일·버전·해상도·라이선스 | 대체 자산과 `ASSET-MISSING` 표시, 대체 사실을 시안 기록에 남김 |
| 언어 구성·주언어 | 실제 원고 기준 | 불명확하면 행간·줄바꿈·혼식 결정을 미결로 남긴다 |
| 독자·관람 거리 | 브리프·채택 절 | 없으면 후보 둘로 시험하고 어느 쪽인지 표시 |
| 제약끼리의 충돌 | 값으로 계산해 확인(예: 고정 판형 + 최소 본문 크기 + 지정 단수) | `CONFLICT`로 기록하고 우선순위는 사람이 정한다 |
| 남은 쟁점의 결정 주체 | `lead-state.md` | 사람 결정 항목은 시안 후보로만 다루고 확정하지 않는다 |
| 채택 방향과 시안 구조 | 채택 절 문장과 그릴 구조 대조 | 어긋나면 §2로 가기 전에 되돌린다 |

확인 결과는 항목별로 `OK` / `ASKED` / `ASSUMED` / `CONFLICT` 중 하나와 근거 위치를 적는다. 침묵을 확인으로 바꾸지 않는다.

### 1.6 인계 판정

`10-intake.md` 마지막 줄에 판정 한 줄과 이유를 남긴다.

| 판정 | 조건 | 다음 |
| --- | --- | --- |
| `READY` | 채택 방향·필요 결과물·근거 ID·제약이 모두 있음 | §2 |
| `PARTIAL` | 일부 결손(예: `DEL` 일부만 인계). 가정 목록과 그 근거가 필수 | 가정을 표시하고 §2 |
| `DIRECT` | 레벨 1 인계 없이 브리프에서 시작 | §1.7의 최소 맥락으로 §2 |
| `BLOCKED` | 판형·매체·콘텐츠·결과물 품목처럼 시안 구조를 정하는 항목이 확인되지 않음 | 그 항목만 묻고 멈춘다 |

필드 목록과 예시는 [인계 기록 계약](../contracts/draft-intake.md)을 따른다.

### 1.7 레벨 1 인계 없이 직접 브리프로 들어온 경우

- 레벨 1(`visual-design-planning`)의 `references/workflow/context-align.md`가 하는 기대 출력·범위 합의를 다시 수행하지 않는다. 레벨 2가 확인하는 것은 시안 구조를 바꾸는 최소 맥락뿐이다: 목적 한 문장, 대상·독자, 매체와 판형(고정값), 실제 콘텐츠, 만들어야 할 결과물(품목·매체), 지켜야 할 제약, 비교할 시안 수.
- 레벨 1의 `brief-vN.md`가 있으면 그것을 브리프로 읽는다. 항목의 상태를 그대로 옮기고, `[추론]`·`[추측]`·`미확인` 항목을 `USER`로 올리지 않는다.
- 브리프에 이미 있는 항목은 다시 묻지 않고 `origin: USER`로 기록한다. 묻는 것은 한 번에 묶고, 답이 없으면 가정으로 진행하되 가정 목록을 시안보다 먼저 보여 준다.
- 레벨 1의 조사(공개 자료·기존 기록·방법 카드)를 대신하지 않는다. 대상·목적의 근거가 없으면 `evidence: []`로 두고, 그래서 생기는 조형 결정은 `NEW`·`INFERRED`로 표시한다.
- 판단이 갈리는 지점(독자, 정보 밀도, 톤)은 임의로 정하지 않고 시안 A/B의 차이 축으로 쓴다. 시안으로 질문에 답하고 사람이 고르게 한다.
- 직접 브리프에서도 같은 `10-intake.md`를 쓰고 `handoff_status: DIRECT`, `assumptions` 목록을 반드시 채운다.

## 2. 조형 번역 · 시안 설계 스펙

기획 근거를 조형 변수로 옮긴다. 각 변환은 근거 ID와 연결하고, 근거 없이 정한 값은 가정으로 표시한다.

### 2.1 번역 규칙

- 값마다 관계를 하나 정한다: `FOLLOWS`(근거 ID를 따름) / `DEVIATES`(근거와 다르게 정함, 이유와 잃는 것을 적음) / `NEW`(근거가 없어 새로 정함, 가정·후보) / `CONFLICT`(근거끼리 충돌, 우선순위는 사람).
- 우선순위는 사용자의 명시값, 레벨 1 확정 제약, 레벨 3의 적용 근거가 확인된 정책, 후보 순이다. 결과물 우선순위는 레벨 1 `DEL` 목록의 값을 그대로 따르고 레벨 2가 다시 매기지 않는다. 아래 단계가 위 단계를 덮지 않는다.
- 수치가 필요한 판단은 식·입력·단위를 함께 남긴다. 계산값은 `DERIVED`, 추정은 `INFERRED`, 근거 없는 선택은 가정이다. 황금비·배율·보정값을 발명하지 않는다.
- 레벨 3의 수식·정책·레퍼런스 지식은 인용하되 레벨 2에서 새 규칙을 승인하지 않고 레벨 3 문서를 고치지 않는다. 같은 값을 두 곳에 적지 않고 `20-translation.md`의 ID로 참조한다.

## 3. 복수 시안 생성 · 근거 매핑

### 3.1 비교 가능한 조건 고정

- 같은 원고, 같은 판형·캔버스 크기, 같은 자산, 같은 렌더 조건(도구·배율·배경)을 쓴다. 다른 것은 선언한 차이 축뿐이다.
- 차이 축은 하나 또는 둘로 제한하고 표에 적는다: 정보 위계, 밀도, 톤, 매체 적합, 제작 난이도 등. 같은 방향의 미세 변형을 A/B라고 부르지 않는다.
- A와 B는 같은 근거에서 갈라진 서로 다른 해석이어야 한다. 어느 근거를 어떻게 읽었는지가 다르고, 그 차이를 `draft.md`에 한 문장씩 적는다.
- 비교하는 A/B는 같은 `DEL` 항목을 대상으로 한다. 서로 다른 품목·매체를 비교 축으로 묶지 않고, 판형이 다른 품목은 같은 차이 축의 시안이 아니라 별도 트랙으로 둔다.

### 3.2 만들 형식과 도구

- 사용할 수 있는 도구를 먼저 확인한다: 정적 HTML/CSS, SVG, 연결된 디자인 도구(Penpot·ArtCraft MCP 등), 이미지 출력. 도구가 있으면 그 도구의 실제 파일로 만들고, 없으면 만들 수 있는 형식으로 축소해 무엇을 잃었는지 밝힌다.
- 아무 형식도 만들 수 없으면 만들었다고 말하지 않는다. 만들지 못한 이유와 필요한 도구·형식을 밝히고, 그 상태로 인계하지 않는다.
- 만든 파일은 브라우저나 도구에서 실제로 열어 확인하고 캡처를 남긴다. 폰트 대체, 문자 잘림, 겹침처럼 렌더에서만 드러나는 것은 확인한 범위에서만 `OUTPUT_INSPECTED`로 적는다.
- 원본 시안 파일은 지우거나 덮어쓰지 않는다. 수정은 새 버전 폴더로 만든다(§4.2).

### 3.3 시안별 기록

`draft-a/draft.md`에 다음을 적는다: 시안 ID, 진입 파일, 다루는 `DEL` ID와 품목·매체(시안 트랙 매핑 기준), 차이 축에서의 위치 한 문장, 따르는 근거 ID, 근거에서 벗어난 결정과 이유, 미확인 값, 렌더 확인 범위. `drafts/INDEX.md`는 시안 ID·대상 `DEL`·진입 파일·캡처·한 줄 설명만 담는다.

### 3.4 근거 추적 표 `30-evidence-map.md`

시안의 파일·요소가 레벨 1의 어느 근거에서 나왔는지 표로 남긴다. 판단이 걸린 요소마다 행을 만들고, 장식적 세부는 묶어 한 행으로 적는다. 행마다 그 값이 어느 `DEL` 품목·매체를 위한 것인지와 레벨 1 근거와의 관계(`FOLLOWS` / `DEVIATES` / `NEW` / `CONFLICT`)를 적는다. 시안 간 우열은 점수로 매기지 않고, 표를 닫기 전에 `10-intake.md`와 양방향으로 맞춘 뒤 말미에 `DEL`별 시안 비교표를 둔다.

열 정의·항목 ID 규칙·관계와 상태 어휘·양방향 검증·시안 비교표 형식과 예시는 [근거 매핑 계약](../contracts/evidence-map.md)이 유일한 기준이다.

## 4. 선택·확정 및 인계 · 수정 루프

### 4.1 선택 받기

- 사람이 시안을 고르면 `40-selection.md`에 날짜, 고른 시안, 고른 이유(사람이 말한 그대로 요약), 함께 지시한 수정, 남긴 대안을 적는다.
- 고르지 않고 "둘 다 괜찮다"거나 "더 봐 달라"고 하면 차이 축으로 한 항목씩 좁혀 다시 묻는다. 레벨 2가 대신 고르지 않는다.
- 고른 이유가 근거와 다르면 근거 ID를 다시 확인해 기록한다. 이유를 근거에 끼워 맞추지 않는다.

### 4.2 수정 루프

- 요청마다 요청 원문 요약, 영향받는 항목 ID·시안·스펙, 재개할 단계, 반영 결과를 적는다.
- 영향받은 시안만 `draft-a-v2`처럼 새 버전으로 만들고 이전 버전과 캡처를 남긴다. `INDEX.md`를 갱신한다.
- 수정이 근거와 충돌하면(예: 확정 판형 위반) 그 사실을 먼저 알리고 사람 결정을 받는다. 레벨 2가 제약을 조용히 깨지 않는다.
- 되돌아갈 단계: 목표·범위가 바뀌면 §1, 조형 값이 바뀌면 §2, 표현만 바뀌면 해당 시안만.
- 같은 항목을 세 번 이상 왕복하면 남은 쟁점과 선택지를 표로 정리해 사람에게 좁혀 제시하고, 더 도는 대신 결정을 기다린다.

### 4.3 확정

- 확정은 사람이 채택을 명시할 때만이다. 채택 전에는 "최종안"이라 부르지 않고 파일명에 `final`을 쓰지 않는다.
- 확정 시 확정 시안을 `drafts/final/`에 복사하고 원본 시안 폴더는 그대로 둔다. 확정 시각, 채택자, 근거를 `40-selection.md`에 함께 남긴다.
- 확정 후 같은 작업의 후속 요청은 기존 `handoff-v1.md`를 고치지 않고 `handoff-v2.md`로 버전을 올린다.

### 4.4 `handoff-v1.md`

제작에 필요한 값을 `visual-design-review`의 `references/design-handoff.md` 계약 형식으로 적는다. 상태는 `30-evidence-map.md`의 값을 그대로 옮기고 승격하지 않는다. design-handoff 필드마다 레벨 2의 어느 기록에서 값을 가져오는지, 여러 `DEL`을 한 스펙에 나누어 적는 방법과 예시는 [인계 계약](../contracts/draft-handoff.md)이 유일한 기준이다.

### 4.5 레벨 3 인계 체크리스트

넘기기 전에 [인계 계약](../contracts/draft-handoff.md)의 '레벨 3 인계 체크리스트'를 항목마다 적힌 확인 방법대로 점검한다. 확인하지 못한 항목은 체크하지 않고 이유를 남긴다.

### 4.6 검수 지적에 대응하기

- 지적마다 영향받는 파일·항목 ID·시안·스펙 값을 표시한다. 조형 문제면 해당 시안과 스펙을, 근거 문제면 레벨 1 인계를 확인한 뒤 사람에게 올리고, 목표 변경이면 §1부터 다시 연다.
- 지적 기록 형식, 판정에 동의하지 않을 때의 처리, 새 값의 반영 위치는 [인계 계약](../contracts/draft-handoff.md)의 '레벨 3 지적에 대응하는 기록'을 따른다. 레벨 3의 판정을 레벨 2에서 뒤집지 않는다.

레벨 2는 조형 결정과 시안 제작까지다. 완성 작품의 비평·심각도 판정·출력 프리플라이트는 레벨 3이 맡는다.
