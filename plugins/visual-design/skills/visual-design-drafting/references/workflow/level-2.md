# 레벨 2 실행 흐름

레벨 2는 레벨 1이 확정한 판단을 조형으로 옮기고, 같은 조건에서 비교할 수 있는 시안을 만든 뒤, 사람이 고른 하나를 제작 가능한 스펙으로 닫는다. 아래 네 단계는 한 번 통과하는 고정 순서가 아니라 결정이 바뀌면 이전 단계로 돌아가는 흐름이다. 단계마다 실행 폴더에 파일 하나가 남고, 다음 단계는 그 파일을 읽어 시작한다.

레벨 2가 대신하지 않는 일: 레벨 1의 자료 조사·방법 카드·근거 작성, 레벨 3의 비평·심각도 판정·출력 프리플라이트. 근거 없는 값·팔레트·비율을 채우지 않고, 사람의 채택을 대신 결정하지 않는다.

## 0. 실행 폴더와 산출물

레벨 1 실행 폴더(`runs/<run-id>/`)가 있으면 그 아래 `drafts/`에 레벨 2 기록을 둔다. 레벨 1 없이 직접 브리프로 들어왔으면 새 `runs/<run-id>/drafts/`를 만들되 `lead-state.md`·`evidence-index.md`는 만들지 않는다(둘은 레벨 1 산출물이다). 실행 폴더의 절대 경로를 `10-intake.md` 첫 줄에 적는다.

| 단계 | 파일 | 남기는 내용 |
| --- | --- | --- |
| 1 | `drafts/10-intake.md` | 레벨 1 인계에서 읽은 채택 방향·근거 ID·제약·미결, 결손 처리, 인계 판정 |
| 2 | `drafts/20-translation.md` | 조형 변수별 값·단위·식, 근거 ID 또는 가정·미결 상태 |
| 3 | `drafts/30-evidence-map.md`, `drafts/draft-a/`·`draft-b/`(필요 시 `draft-c/`) | 시안 산출물과 근거 추적 표 |
| 4 | `drafts/40-selection.md`, `drafts/handoff-v1.md`, `drafts/final/` | 선택·수정 기록, 확정 시안 사본, 제작 스펙 |

시안 폴더마다 진입 파일 하나와 기록을 둔다: 실제 렌더되는 진입 파일(`index.html`, `artboard.svg` 등), 확인용 캡처(`preview.png`), 그 시안의 기록(`draft.md`). 어느 파일이 진입점인지 `drafts/INDEX.md`에 한 줄씩 적는다.

## 1. 인계 자산 로드 · 정합 확인

### 1.1 읽을 파일 정하기

1. 사람이 파일을 지목했으면 그것을 연다.
2. 지목이 없으면 실행 폴더의 `review-v1.md`부터 번호가 매겨진 리뷰 중 번호가 가장 높은 파일을 열되, `lead-state.md`의 사람 판정·시점과 맞는지 확인한다.
3. 채택 기록이 없거나 반려로 끝났으면 채택 여부를 사람에게 묻는다. 리뷰 문장에서 "가장 나은 방향"을 추정해 채택으로 대신하지 않는다.
4. 인계 파일이 아예 없으면 §1.6의 직접 브리프 경로로 간다.

세 파일에서 가져오는 것이 다르다.

| 파일 | 가져오는 것 |
| --- | --- |
| `review-vN.md`(예: `review-v1.md`) | 시안이 답해야 할 질문과 범위, 채택한 방향, 주장별 근거 위치, 완료 기준과 남은 한계 |
| `evidence-index.md` | 근거 ID, 원문 위치, 대상·조건, 발췌, 한계·반례 |
| `lead-state.md` | 사람의 판정과 시점, 확정된 제약, 미결 쟁점의 결정 주체, 보고서 버전 |

### 1.2 `review-vN.md`에서 읽는 순서

레벨 1은 검토용 결과의 앞부분에 합의한 질문에 대한 답과 판단을 바꿀 한계를, 뒤에 채택 시 넘기는 네 필드(채택된 방향과 그 근거 ID, 제작 제약, 미결 쟁점)를 남긴다. 그 순서대로 읽는다.

| 문서 위치 | 읽는 것 | `10-intake.md`로 옮기는 필드 |
| --- | --- | --- |
| 첫 1~2문장 | 합의한 질문에 대한 답, 판단을 바꿀 한계 | `question`, `scope_limit` |
| 채택 절 | 채택된 방향과 그 근거 ID, 제작 제약, 미결 쟁점 | `adopted`, `constraints`, `unresolved` |
| 주장별 근거 | 주장 → 근거 ID → 원문 위치, 근거 수준, 예외 | `evidence` |
| 완료 기준·한계 | 충족·미충족 항목, 자료의 공백 | `gaps` |
| `lead-state.md`의 사람 판정 | 채택 시점, 반려된 안과 사유, 결정 주체 | `decision` |

채택 절이 없는 리뷰는 아직 인계서가 아니다. 방향을 사람이 골랐는지 한 번 묻고, 고르지 않았으면 `PARTIAL`로 두고 후보 방향을 시안 차이 축으로 옮길 수 있는지 사람과 확인한다.

### 1.3 근거 ID 처리

- `evidence-index.md`의 ID를 표기 그대로 쓴다. 번호를 다시 매기거나 이름을 바꾸지 않는다.
- 리뷰가 ID 없이 주장만 적었으면 `evidence-index.md`에서 같은 원문을 찾아 ID를 연결한다. 끝내 없으면 `NO-EVIDENCE`로 표시하고, 그 주장에 기대는 시안 값은 `NEW`(가정·후보)로 둔다.
- 문서에 없는 ID나 원문 위치를 만들지 않는다. 인용 별칭이 필요하면 `ALIAS-01`처럼 별도 접두어를 쓰고 원문 위치를 함께 적는다. 별칭은 근거 ID로 승격되지 않는다.

### 1.4 정합 확인 항목

| 확인 항목 | 확인 방법 | 어긋날 때 |
| --- | --- | --- |
| 판형·매체·마감 | 채택 절과 `lead-state.md`의 제약 대조 | 사람에게 확인. 시안 구조가 달라지므로 §2 전에 멈춘다 |
| 실제 원고 | 원문 텍스트·파일 확보 여부 | 예시 원고로 시험하고 `EXAMPLE-COPY`로 표시. 줄바꿈·수용량은 UNVERIFIED |
| 자산(이미지·로고·서체) | 파일·버전·해상도·라이선스 | 대체 자산과 `ASSET-MISSING` 표시, 대체 사실을 시안 기록에 남김 |
| 언어 구성·주언어 | 실제 원고 기준 | 불명확하면 행간·줄바꿈·혼식 결정을 미결로 남긴다 |
| 독자·관람 거리 | 브리프·채택 절 | 없으면 후보 둘로 시험하고 어느 쪽인지 표시 |
| 제약끼리의 충돌 | 값으로 계산해 확인(예: 고정 판형 + 최소 본문 크기 + 지정 단수) | `CONFLICT`로 기록하고 우선순위는 사람이 정한다 |
| 미결 쟁점의 결정 주체 | `lead-state.md` | 사람 결정 항목은 시안 후보로만 다루고 확정하지 않는다 |
| 채택 방향과 시안 구조 | 채택 절 문장과 그릴 구조 대조 | 어긋나면 §2로 가기 전에 되돌린다 |

확인 결과는 항목별로 `OK` / `ASKED` / `ASSUMED` / `CONFLICT` 중 하나와 근거 위치를 적는다. 침묵을 확인으로 바꾸지 않는다.

### 1.5 인계 판정

`10-intake.md` 마지막 줄에 판정 한 줄과 이유를 남긴다.

| 판정 | 조건 | 다음 |
| --- | --- | --- |
| `READY` | 채택 방향·근거 ID·제약이 모두 있음 | §2 |
| `PARTIAL` | 일부 결손. 가정 목록과 그 근거가 필수 | 가정을 표시하고 §2 |
| `DIRECT` | 레벨 1 인계 없이 브리프에서 시작 | §1.6의 최소 맥락으로 §2 |
| `BLOCKED` | 판형·매체·콘텐츠처럼 시안 구조를 정하는 항목이 확인되지 않음 | 그 항목만 묻고 멈춘다 |

필드 목록과 예시는 [인계 기록 계약](../contracts/draft-intake.md)을 따른다.

### 1.6 레벨 1 인계 없이 직접 브리프로 들어온 경우

- 레벨 1(`visual-design-planning`)의 `references/workflow/context-align.md`가 하는 기대 출력·범위 합의를 다시 수행하지 않는다. 레벨 2가 확인하는 것은 시안 구조를 바꾸는 최소 맥락뿐이다: 목적 한 문장, 대상·독자, 매체와 판형(고정값), 실제 콘텐츠, 지켜야 할 제약, 비교할 시안 수.
- 브리프에 이미 있는 항목은 다시 묻지 않고 `origin: USER`로 기록한다. 묻는 것은 한 번에 묶고, 답이 없으면 가정으로 진행하되 가정 목록을 시안보다 먼저 보여 준다.
- 레벨 1의 조사(공개 자료·기존 기록·방법 카드)를 대신하지 않는다. 대상·목적의 근거가 없으면 `evidence: []`로 두고, 그래서 생기는 조형 결정은 `NEW`·`INFERRED`로 표시한다.
- 판단이 갈리는 지점(독자, 정보 밀도, 톤)은 임의로 정하지 않고 시안 A/B의 차이 축으로 쓴다. 시안으로 질문에 답하고 사람이 고르게 한다.
- 직접 브리프에서도 같은 `10-intake.md`를 쓰고 `handoff_status: DIRECT`, `assumptions` 목록을 반드시 채운다.

## 2. 조형 번역 · 시안 설계 스펙

기획 근거를 조형 변수로 옮긴다. 각 변환은 근거 ID와 연결하고, 근거 없이 정한 값은 가정으로 표시한다.

### 2.1 번역 규칙

- 값마다 관계를 하나 정한다: `FOLLOWS`(근거 ID를 따름) / `DEVIATES`(근거와 다르게 정함, 이유와 잃는 것을 적음) / `NEW`(근거가 없어 새로 정함, 가정·후보) / `CONFLICT`(근거끼리 충돌, 우선순위는 사람).
- 우선순위는 사용자의 명시값, 레벨 1 확정 제약, 레벨 3의 적용 근거가 확인된 정책, 후보 순이다. 아래 단계가 위 단계를 덮지 않는다.
- 수치가 필요한 판단은 식·입력·단위를 함께 남긴다. 계산값은 `DERIVED`, 추정은 `INFERRED`, 근거 없는 선택은 가정이다. 황금비·배율·보정값을 발명하지 않는다.
- 레벨 3의 수식·정책·레퍼런스 지식은 인용하되 레벨 2에서 새 규칙을 승인하지 않고 레벨 3 문서를 고치지 않는다. 같은 값을 두 곳에 적지 않고 `20-translation.md`의 ID로 참조한다.

### 2.2 영역별 산출 기준

| 조형 영역 | 정할 값 | 참조 | 근거가 없을 때 |
| --- | --- | --- | --- |
| 레이아웃·그리드 | 판면, 여백, 단 수·거터·단폭, 기준선 격자, 요소 정렬 관계 | `visual-design-review`의 `references/composition.md`, 판면 수용량은 `typography-relations.md`의 T-MEASURE·T-CAPACITY | 그리드 후보 둘을 만들고 각 후보를 지지하는 근거를 적는다. 미결로 두고 시안 차이 축으로 넘길 수 있다 |
| 서체 페어링·타이포 위계 | 역할별 서체·굵기·크기·행간·자간·줄 길이·정렬, 크기비 | `typography-relations.md`의 T-METRICS·T-SPACING·T-LEADING·T-HIERARCHY, `typography-presets.md`의 A~H | 역할별 후보와 판단 기준을 제시하고 미결. 실제 렌더 판독 전에는 UNVERIFIED |
| 한글·라틴 혼식 | 한 기준선 간격, 보조 언어의 크기·굵기 조정 여부, 줄바꿈·금칙 조건 | `typography-relations.md`, `mixed-script-knowledge.md` | 주언어가 불명확하면 행간·줄바꿈을 미결로 남긴다 |
| 컬러·톤 | 색의 역할별 값, 색 공간·프로파일, 대비 목표와 측정 여부 | `composition.md`의 색채 상호작용 | 색 역할만 정하고 색값은 후보 둘로 남긴다. 승인 없이 팔레트를 확정하지 않는다 |
| 이미지·자산 | 크롭·비율·해상도·배치, 대체 자산 | `identity-production.md`(출력 규격이 걸릴 때) | `ASSET-MISSING`으로 표시하고 대체 사실을 기록 |
| 레퍼런스 재사용 | 재사용할 원리와 이 작업에서 새로 정한 값 | `reference-analysis.md` | 사례 ID와 관측 근거 없이 원작 수치를 상속하지 않는다 |

영역별 절차·식·예시는 [조형 번역 기준](../form-translation.md)에 있다.

`typography-presets.md`의 A~H는 현재 작업의 명시적 opt-in 또는 독립적으로 확인된 활성 프로파일이 있을 때만 후보로 인용한다. 주언어나 인쇄 조건이 맞는다는 사실로 레벨 2가 활성화를 선언하지 않는다. 활성 근거가 없으면 행간 배율은 미결이고, 계산하는 값은 사용자가 지정한 배율에 한한다.

### 2.3 `20-translation.md`

| 번역 ID | 영역 | 값·단위 | 식·입력 | provenance | decision status | verification |
| --- | --- | --- | --- | --- | --- | --- |
| T-01 | 그리드 | 38 mm | (148 − 12×2 − 5×2) / 3 | DERIVED | DETERMINED | FORMULA_CHECKED |

- `provenance`·`decision status`·`verification`은 `design-handoff` 계약의 어휘를 그대로 쓴다. 전체 목록과 뜻은 [근거 매핑 계약](../contracts/evidence-map.md)에 있다.
- 말미에 미결 목록(쟁점·결정 주체), 가정 목록(가정·근거·영향), 시안에서 확인할 항목을 적는다.
- 게이트: 그리드·위계·매체 중 구조를 정하는 항목이 미결이면 시안을 만들지 않고 그 항목만 사람에게 묻는다. 색·디테일·표현 요소의 미결은 후보로 두고 시안을 진행할 수 있다.

## 3. 복수 시안 생성 · 근거 매핑

### 3.1 비교 가능한 조건 고정

- 같은 원고, 같은 판형·캔버스 크기, 같은 자산, 같은 렌더 조건(도구·배율·배경)을 쓴다. 다른 것은 선언한 차이 축뿐이다.
- 차이 축은 하나 또는 둘로 제한하고 표에 적는다: 정보 위계, 밀도, 톤, 매체 적합, 제작 난이도 등. 같은 방향의 미세 변형을 A/B라고 부르지 않는다.
- A와 B는 같은 근거에서 갈라진 서로 다른 해석이어야 한다. 어느 근거를 어떻게 읽었는지가 다르고, 그 차이를 `draft.md`에 한 문장씩 적는다.

### 3.2 만들 형식과 도구

- 사용할 수 있는 도구를 먼저 확인한다: 정적 HTML/CSS, SVG, 연결된 디자인 도구(Penpot·ArtCraft MCP 등), 이미지 출력. 도구가 있으면 그 도구의 실제 파일로 만들고, 없으면 만들 수 있는 형식으로 축소해 무엇을 잃었는지 밝힌다.
- 아무 형식도 만들 수 없으면 만들었다고 말하지 않는다. 만들지 못한 이유와 필요한 도구·형식을 밝히고, 그 상태로 인계하지 않는다.
- 만든 파일은 브라우저나 도구에서 실제로 열어 확인하고 캡처를 남긴다. 폰트 대체, 문자 잘림, 겹침처럼 렌더에서만 드러나는 것은 확인한 범위에서만 `OUTPUT_INSPECTED`로 적는다.
- 원본 시안 파일은 지우거나 덮어쓰지 않는다. 수정은 새 버전 폴더로 만든다(§4.2).

### 3.3 시안별 기록

`draft-a/draft.md`에 다음을 적는다: 시안 ID, 진입 파일, 차이 축에서의 위치 한 문장, 따르는 근거 ID, 근거에서 벗어난 결정과 이유, 미확인 값, 렌더 확인 범위. `drafts/INDEX.md`는 시안 ID·진입 파일·캡처·한 줄 설명만 담는다.

### 3.4 근거 추적 표 `30-evidence-map.md`

시안의 파일·요소가 레벨 1의 어느 근거에서 나왔는지 표로 남긴다. 판단이 걸린 요소마다 행을 만들고, 장식적 세부는 묶어 한 행으로 적는다.

| 항목 ID | 시안 | 조형 요소 | 값·단위 | 레벨 1 근거 ID | 번역 ID | 관계 | 상태 | 비고 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| E-GRID-01 | A | 본문 단폭 | 38mm | EV-04 | T-01 | FOLLOWS | DETERMINED / FORMULA_CHECKED | 판형 고정값에서 계산 |
| E-TYPE-03 | B | 제목 크기 | 28pt | NO-EVIDENCE | T-07 | NEW | CANDIDATE / UNVERIFIED | 후보값, 사람 선택 필요 |

- `항목 ID`는 조형 판단 단위로 붙인다(`E-GRID-01`, `E-TYPE-03`, `E-COLOR-02`). 같은 항목을 A와 B가 다르게 채우면 행을 둘로 나눈다.
- 양방향으로 맞춘다: `10-intake.md`의 근거 ID가 표에 모두 나오거나 "쓰지 않음 + 이유"로 남고, 표의 레벨 1 ID는 모두 `10-intake.md`에 있다. 없는 ID를 사후에 만들어 붙이지 않는다.
- 시안 간 우열을 점수로 매기지 않는다. 차이는 값과 근거로 적고 선택은 사람이 한다.
- 시안 비교표(차이 축에서의 위치·핵심 판단·제작 난이도·남은 위험)를 `30-evidence-map.md` 말미에 둔다. 시안이 바꾸는 판단과 남는 위험이 한눈에 보여야 사람이 고를 수 있다.

표의 열 정의·관계 어휘·검증 절차는 [근거 매핑 계약](../contracts/evidence-map.md)을 따른다.

## 4. 선택·확정 및 인계 · 수정 루프

### 4.1 선택 받기

- 사람이 시안을 고르면 `40-selection.md`에 날짜, 고른 시안, 고른 이유(사람이 말한 그대로 요약), 함께 지시한 수정, 남긴 대안을 적는다.
- 고르지 않고 "둘 다 괜찮다"거나 "더 봐 달라"고 하면 차이 축으로 한 항목씩 좁혀 다시 묻는다. 레벨 2가 대신 고르지 않는다.
- 고른 이유가 근거와 다르면 근거 ID를 다시 확인해 기록한다. 이유를 근거에 끼워 맞추지 않는다.

### 4.2 수정 루프

- 요청마다 요청 원문 요약, 영향받는 항목 ID·시안·스펙, 재개할 단계, 반영 결과를 적는다.
- 영향받은 시안만 `draft-a-v2`처럼 새 버전으로 만들고 이전 버전과 캡처를 남긴다. `INDEX.md`를 갱신한다.
- 수정이 근거와 충돌하면(예: 확정 판형 위반) 그 사실을 먼저 알리고 사람 결정을 받는다. 레벨 2가 제약을 조용히 깨지 않는다.
- 되돌아갈 단계: 목표·범위가 바뀌면 §1, 조형 값이 바뀌면 §2, 표현만 바뀌면 해당 시안만.
- 같은 항목을 세 번 이상 왕복하면 남은 쟁점과 선택지를 표로 정리해 사람에게 좁혀 제시하고, 더 도는 대신 결정을 기다린다.

### 4.3 확정

- 확정은 사람이 채택을 명시할 때만이다. 채택 전에는 "최종안"이라 부르지 않고 파일명에 `final`을 쓰지 않는다.
- 확정 시 확정 시안을 `drafts/final/`에 복사하고 원본 시안 폴더는 그대로 둔다. 확정 시각, 채택자, 근거를 `40-selection.md`에 함께 남긴다.
- 확정 후 같은 작업의 후속 요청은 기존 `handoff-v1.md`를 고치지 않고 `handoff-v2.md`로 버전을 올린다.

### 4.4 `handoff-v1.md`

제작에 필요한 값을 `visual-design-review`의 `references/design-handoff.md` 계약 형식으로 적는다. 필드 대응은 다음과 같다.

| design-handoff 필드 | 레벨 2에서 채우는 값 |
| --- | --- |
| Brief & constraints | `10-intake.md`의 제약·미결·가정, 실제 콘텐츠와 자산 상태 |
| Design values | `20-translation.md`와 확정 시안의 값, 객체·관계 ID, 단위·원점·좌표계, 식 ID와 적용 조건 |
| Provenance / Decision status / Verification status | `30-evidence-map.md`의 상태를 그대로. 다른 값으로 승격하지 않는다 |
| Rule basis | 적용한 레벨 3 규칙만 `rule_id`·범위·조건·예외·검증 방법과 함께 |
| Reconstruction model / Adjustments | 레퍼런스 재사용·보정을 실제로 했을 때만, 사례 ID로 연결 |
| Unresolved | 남은 미결·충돌과 결정 주체 |
| Verification request | 레벨 3에 확인을 요청할 실제 속성과 허용 편차(근거가 있을 때만) |

계약 예시와 필드별 작성 방법은 [인계 계약](../contracts/draft-handoff.md)을 따른다.

### 4.5 레벨 3 인계 체크리스트

- [ ] 확정 시안의 진입 파일 경로와 렌더 캡처, `drafts/INDEX.md` 최신 상태
- [ ] `handoff-v1.md`의 필수 필드가 값·출처·상태와 함께 채워짐
- [ ] `10-intake.md`·`20-translation.md`·`30-evidence-map.md`의 근거 ID가 양방향으로 맞음
- [ ] 미결·가정·UNVERIFIED 목록과 각 결정 주체
- [ ] 레벨 1 채택 방향과의 정합, 벗어난 결정과 그 이유
- [ ] 레벨 2가 대신하지 않은 것(비평·심각도·프리플라이트)과 검수받을 범위
- [ ] 인계문 한 단락: 무엇을 검수받는지, 어떤 판단이 아직 열려 있는지

항목별 확인 방법은 [인계 계약](../contracts/draft-handoff.md)의 체크리스트에 있다.

### 4.6 검수 지적에 대응하기

- 지적마다 영향받는 파일·항목 ID·시안·스펙 값을 표시한다. 조형 문제면 해당 시안과 스펙을, 근거 문제면 레벨 1 인계를 확인한 뒤 사람에게 올리고, 목표 변경이면 §1부터 다시 연다.
- 레벨 3의 판정을 레벨 2에서 뒤집지 않는다. 동의하지 않으면 판정과 다른 근거·관찰을 함께 적어 사람이 정하게 한다.
- 검수에서 새로 정한 값은 `20-translation.md`와 `30-evidence-map.md`에 반영하고, 출처가 레벨 3 검수인지 사람 결정인지 구분해 적는다.

레벨 2는 조형 결정과 시안 제작까지다. 완성 작품의 비평·심각도 판정·출력 프리플라이트는 레벨 3이 맡는다.
