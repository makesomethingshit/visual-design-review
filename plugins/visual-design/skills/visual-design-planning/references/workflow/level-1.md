# 레벨 1 실행 흐름

1. [실행 기록 관리](lead-state-lifecycle.md)에 따라 새 의뢰인지 후속인지 먼저 확인한다. 작업 공간 아래에 실행 경로를 확정하고 두 기록 파일을 그 경로에 연다. [공용 방법론 인덱스](../methods/01.methods-index.md)를 훑어 가능한 출력 유형을 파악한다.
2. [맥락 확인](context-align.md)에서 이미 주어진 내용을 보존하고 결과를 바꾸는 정성 질문을 한 번에 하나씩 묻는다. 정리한 브리프를 `brief-v1.md`에 저장하고 질문·출력·범위·자료·판정할 수 없는 범위를 실행 기록에 정리한 뒤 별도 승인을 요구하지 않고 [과제 분할](task-decomposition.md)로 질문, 필수 근거, 결과물, 완료 기준, 선행 관계를 구체화한다. 시각·표현 방향 후보는 만들지 않는다.
3. 과제마다 인덱스의 기대 출력이 요구 항목·단위·비교 범위를 충족하는지 확인한다. 맞는 카드가 없으면 다른 카드를 검토한다. 끝내 맞는 카드가 없으면 과제와 원래 완료 기준을 유지하고 미수행 사유를 기록한다. 카드가 있으면 자료, 접근 권한, 실행 범위를 확인하고 두 판정의 이유를 기록한다.
4. 입력이 부족하면 정성적 의도·우선순위는 다음 한 질문으로 확인하고, 확인 가능한 정량 조건은 기존 공개·제공 자료를 찾는 범위로 좁혀 [배정과 결과 형식](task-exchange.md)에 따라 하위 리서치를 배정한다. 중간 조건 합의를 별도 승인 절차로 요구하지 않는다. 회신에는 범위, 확인한 원문·시점·위치, 충돌, 남은 공백이 필요하다. 실제로 공백을 줄이는 새 근거가 확보되면 자료 조건을 다시 판정한다. 시작 전에 정한 검색 범위와 시도 한도에 도달했거나, 회신에 새 근거가 없거나, 권한·범위가 맞지 않으면 사유를 기록한다. 진행 중 사용자에게 새 조사를 맡기지 않는다.
5. 두 판정을 통과한 분석은 [배정과 결과 형식](task-exchange.md)에 따라 실행한다. 독립 과제는 병렬 배정할 수 있다. 선행 과제의 결과가 확보된 뒤 의존 과제를 배정한다. 필수 결과를 얻지 못하면 의존 과제에는 어떤 입력이 빠졌는지 기록하고 미수행으로 닫는다. 별도 하위 에이전트를 호출할 수 없는 환경에서는 총괄이 같은 입출력 계약으로 순차 실행하고 실행 방식을 기록한다.
6. 모든 과제가 완료·부분 완료·미수행·실패 중 하나가 되면 취합한다. 대기 또는 진행 과제를 최종 보고에서 누락하지 않는다. 결과와 완료 기준을 대조하고 주장별 근거 위치를 확인한다. 관련 항목을 묶고 이름을 붙인다. 상충 자료, 묶이지 않은 항목, 한계, 근거 부족과 모든 종료 사유를 함께 남긴다. 중요도와 채택 여부는 사람에게 맡긴다.
7. 검토용 결과의 첫 1~2문장에 합의한 질문에 대한 답과 판단을 바꿀 한계를 쓴다. 이어 주장, 근거 위치, 추론 경로, 예외와 완료 기준 충족 여부를 제시한다. 주장마다 [측정/기록]·[추론]·[추측] 가운데 하나를 붙인다. 이 태그 규칙은 하위 회신뿐 아니라 총괄 자신의 검토 보고서에도 똑같이 적용한다(규칙 원문은 [배정과 결과 형식](task-exchange.md)). 검토용 결과를 실행 폴더의 review-v1.md에 저장하고 사람에게 전달한다. 보완한 결과는 review-v2.md처럼 다음 버전 파일에 쓴다. 사람이 채택하면 **채택 시점의 최신 리뷰 파일(review-vN.md) 안에 `## 채택` 절을 열고** 첫 줄에 기준 브리프 버전을 적고 인계 5필드(채택 방향·필요 결과물·근거 ID·제작 제약·남은 쟁점)를 그 절에 표로 적어 인계한다. 채택 방향은 과제 방향(풀 문제·우선 대상·우선순위·정보 단위와 순서)이며 시각·표현 방향이 아니다. 인계 전에 조사·삼각검증을 마친 근거로 그 문제를 풀기 위해 실제로 제작해야 할 디자인 결과물 목록(`필요 결과물`)까지 정해, 항목마다 품목·매체·목적·우선순위·연결 근거 ID를 `DEL-xx` ID와 함께 채택 절에 담는다. 결과물 목록은 무엇을 만들지 정하는 것이지 만드는 것이 아니므로 파일 없이 목록만 적는다. 채택 때문에 새 버전 파일을 만든다면 검토 본문 전체를 옮긴 뒤 채택 절을 붙인다(레벨 2는 번호가 가장 높은 리뷰 파일을 연다). 별도 `handoff.md` 파일이나 대화 요약만으로 인계하지 않는다 — 레벨 2(`visual-design-drafting`)는 채택 절이 있는 리뷰 파일만 인계서로 읽고, 채택 절이 없으면 `PARTIAL`로 두고 방향을 다시 묻는다. 필드 순서·ID 부여·파일명 규칙은 [실행 기록 관리](lead-state-lifecycle.md)의 '인계 기록' 절을 따른다. 다음 단계는 `visual-design-drafting`(레벨 2)이며, 레벨 1은 채택 절까지 쓰고 시안·조판·목업 파일은 만들지 않는다. 보완이면 영향받은 과제만 다시 열고, 목표·범위가 바뀌면 맥락부터 확인한다. 반려된 안은 결정과 사유를 기록하고 종료한다.

총괄의 배정과 취합은 두 역할 단계다. 자료 확인이나 선행 과제의 결과에 따라 배정이 추가될 수 있다. 사용자가 명시한 최종 승인·채택 전에는 결과를 미결·승인 대기로 표시할 수 있지만, 중간 단계에서 추가 승인 장벽을 만들지 않는다.

## 브리프만 요청한 경우

- 기대 출력이 브리프 자체일 때(사용자가 브리프나 의뢰 정리만 원하거나 조사가 필요 없다고 말한 경우) 1·2단계만 진행한다. 실행 경로와 `lead-state.md`를 열고, 맥락 확인으로 `brief-v1.md`를 쓴 뒤 사람에게 전달하고 멈춘다. 과제 분할·조사·`review-vN.md`·채택 절은 만들지 않는다. `evidence-index.md`는 제공 자료나 공개 기록을 근거로 등록했을 때만 쓴다.
- 브리프만 원하는지 조사까지 원하는지가 결과를 바꾸는데 요청에서 알 수 없으면, 그 선택을 맥락 질문 하나로 묻는다.
- 전달 답변의 첫 1~2문장에 목표와 결과물, 그리고 판단을 가장 크게 바꿀 미확인 항목을 쓴다. 미확인 항목마다 확인 방법(질문 / 기존 자료 조사)을 붙인다.
- 사람이 조사를 원하면 같은 실행 경로에서 3단계부터 이어 간다. 바로 시안으로 가면 레벨 2(`visual-design-drafting`)가 `brief-vN.md`를 직접 브리프로 읽는다. 근거 조사와 채택을 거치지 않았으므로 레벨 2의 인계 판정은 `DIRECT`다.
