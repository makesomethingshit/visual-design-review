# 실행 기록 관리

- 실행 시 사용자 작업 공간의 `runs/<run-id>/`에 총괄용 `lead-state.md`와 공유용 `evidence-index.md`를 만든다. 예를 들어 작업 공간이 프로젝트 폴더이고 실행 ID가 exhibition-01이면 두 파일을 모두 프로젝트 폴더의 runs/exhibition-01/에 둔다. 새 실행은 중복되지 않는 경로를 쓴다. 같은 의뢰의 후속이나 재개는 확인된 기존 경로와 버전을 이어 쓴다. 연속성이 불명확하면 확인 후 결정한다. 새 의뢰에는 새 경로를 할당해 이전 작업 맥락이 섞이지 않게 한다.
- `lead-state.md`에는 의뢰의 질문·범위·합의 출력, 과제 ID·버전·선행 관계·완료 기준, 방법 선택 이유, 자료 충분성, 시도 한도와 검색 결과, 과제 상태, 사람의 판정 및 보고서 버전을 적는다. 검토 보고서는 같은 폴더의 review-v1.md에 저장하고, 보완할 때는 review-v2.md처럼 번호를 올린다. 이 파일명과 안 ID, 사람의 결정·시점·남은 쟁점을 lead-state.md에 연결한다. 같은 슬롯의 이전 임시 기록 정리가 필요하면 사용자가 정리 대상으로 확인한 파일에 한한다.
- `evidence-index.md`의 각 항목에 고유 근거 ID, 원문 링크나 제공 파일, 페이지·문단·행·타임스탬프 중 실제 위치, 시점, 대상·조건, 필요한 발췌, 사용 맥락, 한계나 반례를 적는다. 리서치 회신은 총괄이 확인하고 등록한다.
- 두 파일은 총괄이 관리한다. 하위에는 [배정과 결과 형식](task-exchange.md)에 따라 필요한 근거 항목을 전달한다. 공유 색인의 근거 ID와 원문 위치를 배정문에도 유지한다. 역할별 접근은 작업 지침으로 관리한다.
- 과제 상태는 대기·진행·완료·부분 완료·미수행·실패를 사용한다. 후속 요청으로 다시 열기 전까지 이전 결과와 근거를 유지한다.

## 인계 기록 — `review-vN.md`의 `## 채택` 절

사람이 방향을 채택하면 레벨 1은 **채택 시점의 최신 리뷰 파일(`review-vN.md`)** 에 `## 채택` 절을 만들어 그 안에 인계를 적는다. 그 파일은 채택 대상이 된 검토 본문을 함께 담아야 하고, 채택 때문에 새 버전 파일을 만든다면 검토 본문 전체를 옮긴 뒤 채택 절을 붙인다(레벨 2는 번호가 가장 높은 리뷰 파일을 연다). 별도 `handoff.md` 파일이나 대화 요약으로 인계하지 않는다. 레벨 2(`visual-design-drafting`)는 채택 절이 있는 리뷰 파일만 인계서로 읽고, 채택 절이 없으면 `PARTIAL`로 두고 방향을 다시 묻는다.

채택 절에는 아래 네 필드를 이 순서와 이름으로 적는다. 표의 이름을 바꾸거나 다른 이름을 새로 만들지 않는다.

| 순서 | 필드 | 적는 내용 | ID |
| --- | --- | --- | --- |
| 1 | **채택 방향** | 사람이 고른 방향의 이름·요약과, 후보 중 반려된 방향 및 그 사유 | `DIR-01` |
| 2 | **근거 ID** | 채택 방향과 제약을 뒷받침하는 `evidence-index.md`의 근거 ID와 원문 위치 | `EV-01` |
| 3 | **제작 제약** | 다음 단계가 지켜야 하는 확정값(판형·매체·수량·마감·일정·필수 문구·자산 조건 등)과 출처 | `C-01` |
| 4 | **남은 쟁점** | 아직 정해지지 않은 항목, 결정 주체, 다음 단계에 미치는 영향 | `U-01` |

ID 규칙:

- 후보 방향은 검토 보고서에서 `DIR-01`처럼 두 자리 번호를 붙인다. 사람이 고른 후보도 자기 ID를 유지하고, 반려된 방향은 사유와 함께 남긴다. 채택 절의 채택 방향은 사람이 고른 `DIR-xx`를 가리킨다.
- 제작 제약은 `C-01`부터, 남은 쟁점은 `U-01`부터 두 자리 번호로 매긴다. 번호는 리뷰 파일 안에서만 유일하면 되고, 다음 리뷰 버전에서 이어 쓴다.
- 근거 ID는 `evidence-index.md`가 이미 부여한 `EV-xx`를 표기 그대로 쓴다. 채택 절에서 새 근거 ID를 만들지 않고, 근거가 없는 주장은 `NO-EVIDENCE`로 둔다.
- 레벨 2는 이 ID를 다시 매기지 않고, 문서에 없는 ID를 만들지 않는다. 레벨 1이 ID 없이 인계한 경우(이전 버전 리뷰나 다른 경로에서 온 리뷰)에만 레벨 2가 인계 로드 시 읽은 순서대로 부여하고, 그 사실을 `10-intake.md`의 `id_origin`에 `LEVEL2_NORMALIZED`로 적는다.
- `lead-state.md`에 채택 절이 있는 리뷰 파일명·버전, 채택 시점, 결정자, 채택·반려된 `DIR` ID를 연결한다. 채택 전에는 `review-vN.md`에 채택 절을 만들지 않고, 초안 단계의 후보는 `DIR` ID와 "미채택" 표시만 붙인다.

레벨 2 계약의 키 `adopted`·`constraints`·`unresolved`는 이 네 필드 가운데 1·3·4번을 그대로 옮긴 것이고, `evidence`는 2번 근거 ID를 담는다. 키 이름은 영문이어도 필드 이름과 순서는 이 표를 따른다.
